# MealMap v1 规格

> 工作名 `MealMap`，包名 `dev.mealmap.app`。中文名与许可证待定（见"开放问题"）。
> 产品定位：记录"什么时候、在哪里、吃了什么"的个人饮食日志。地图和日历是同一份数据的两种视图。完全离线、无账号、无社交。

## 1. 目标与非目标

**v1 要解决的事**：让用户用最低摩擦记下一餐（时间、城市、菜系、菜品、照片、标签、备注），并能通过**美食地图**和**美食日历**回看自己的饮食足迹。

**v1 明确不做**：

- 社交、看别人的记录、公开分享
- 账号、云同步、云端存图（**只预留接口**，见 §7）
- "今天吃什么"推荐
- GPS 定位、真实地图底图与街道级细节
- 多用户、多设备实时协作
- iOS 构建（代码结构留路，不出包）
- 搜索框、独立统计页、独立记录列表页

## 2. 领域模型

术语以 `GLOSSARY.md` 为准。

```
Cuisine 1 ──< Meal >── 1 City（来自内置数据集，存 city_code）
Meal 1 ──< Dish
Meal 1 ──< Photo
Meal >──< Tag（多对多）
```

### 实体

| 实体 | 字段 | 约束 |
|---|---|---|
| `Meal` | `id`(uuid), `eaten_on`(date), `slot`(breakfast/lunch/dinner/snack, nullable), `city_code`, `cuisine_id`, `note`, `created_at`, `updated_at` | 一餐一个菜系；城市必填；日期必填 |
| `Dish` | `id`, `meal_id`, `name`, `position` | 0..n，自由文本 |
| `Photo` | `id`, `meal_id`, `file_name`, `thumb_name`, `width`, `height`, `position` | 0..9 张 |
| `Cuisine` | `id`, `name`, `is_builtin`, `sort_order`, `archived_at` | 单选来源；可新增、可改名；被引用时只能归档不能删除 |
| `Tag` | `id`, `name`, `created_at` | 2–12 字；同名复用；单餐最多 10 个 |
| `MealTag` | `meal_id`, `tag_id` | 联合主键 |

### 索引

- `Meal(eaten_on)`、`Meal(city_code)`、`Meal(cuisine_id)`、`Photo(meal_id)`

## 3. 内置数据

- **菜系表**（首批，用户可增改）：川、粤、湘、鲁、苏、浙、闽、徽、东北、西北、云贵、京/本帮、潮汕客家、日料、韩餐、东南亚、南亚、中东、意法西餐、拉美、快餐/其他。
  注意：菜系**不是**省级行政区，川菜可以出现在任何城市。
- **城市数据集**：省 + 地级市，`city_code` 用行政区划代码；城市需带坐标供地图气泡使用。来源与精简程度见"开放问题"。
- **省级 GeoJSON**：用于地图着色，需做几何简化以控制体积与渲染性能。

## 4. 页面与流程

### 4.1 美食地图（首页）

- 中国省级行政区按 **Meal 数量**着色（单一编码，图例可见）；城市按数量出气泡。
- 顶部年份切换：全部 / 今年 / 指定年份。
- 点击省份：展示该省的城市气泡与各自数量。
- 入口：右下角 FAB「记一餐」。

### 4.2 美食日历

- 默认月视图：格子标出当天是否有记录、当天照片缩略图或菜系色点。
- 点击某天 → 当天 Meal 列表（底部弹层）→ 点击进详情/编辑。**这是详情页唯一入口**（v1 无列表页）。
- 顶部可切到年视图：365 格只读热力图（有/无记录），不可点。

### 4.3 记录详情 / 编辑

- 展示与编辑 §2 的全部字段；照片可增删排序；标签可增删。
- 删除 Meal 时级联删除照片与缩略图文件。

### 4.4 设置

- 菜系管理（新增/改名/归档）、标签管理
- 导出 / 导入（含"一键移机"引导，见 §6）
- 关于（版本、开源许可）

## 5. 照片

- 多选，单餐上限 9 张。
- 选中后立即拷贝进 App 私有目录，**不依赖相册 URI**。
- 压缩：长边 2048、JPEG q80；另存 200px 缩略图供列表/日历使用。
- DB 只存文件名；读取时拼接当前私有目录路径。
- 删除 Meal 时级联删除原图与缩略图；导入时按 zip 内文件名重建。

## 6. 导出 / 导入 / 一键移机

- 导出：生成 `mealmap-export-<yyyyMMdd>.zip`，内含 `data.json`（带 `format_version`）、`photos/`、`thumbs/`。
- 一键移机：旧机走"移机"引导 → 导出 zip → 调系统分享面板（附近分享/微信/网盘/文件均可）；新机"导入" → 选 zip → 校验版本 → 事务式写入。
- App 自身不实现网络传输，不需要 INTERNET 权限。
- 导入冲突：ID 相同则跳过并计数；版本不兼容则明确报错，不半途写入。

## 7. 预留云同步的接口（v1 不实现）

- 所有读写经 `MealRepository` 等接口，UI 不依赖 drift 的生成类型。
- 实体带稳定 UUID 与 `created_at` / `updated_at`，可做 last-write-wins。
- 导出格式带 `format_version`，未来同步协议可复用同一 DTO。

## 8. 非功能要求

- 完全离线可用；release 构建不声明 INTERNET 权限。
- 冷启动到地图可交互 ≤ 2s（中端机）。
- 1 万条 Meal 下列表/日历/地图聚合不卡顿。
- 照片列表必须按目标尺寸解码（禁止全分辨率解码）。
- 代码未来公开到 GitHub：无密钥、`.gitignore` 覆盖 `build/`、`.dart_tool/`，补 README 与 LICENSE。

## 9. 验收标准（节选）

1. 全新安装 → 记一餐（含 3 张照片、2 个标签）→ 地图上对应省份颜色加深、城市出气泡。
2. 切到"今年"后，跨年的记录不出现在地图上；切回"全部"恢复。
3. 日历月视图能看到当天缩略图；点开能看到当天所有 Meal 并进入详情修改菜系。
4. 删除一餐后，照片文件与缩略图从私有目录消失。
5. 导出 zip → 清空 App 数据 → 导入 → 照片、标签、菜系全部恢复，且无孤儿文件。
6. 添加第 10 个标签时被拒绝并给出提示；输入 13 字标签时被拒绝。
7. release APK 在飞行模式下全部功能可用。

## 10. 开放问题

- App 中文名、应用图标、LICENSE 类型（MIT / Apache-2.0 / 其他）。
- 城市数据集来源（民政部行政区划代码 vs 第三方整理）与是否含县级。
- 省级 GeoJSON 的简化等级与体积预算。
- 餐次 `slot` 是否按时间自动推断（默认不推断，用户可不填）。
